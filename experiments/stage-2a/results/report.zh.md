# Stage 2A Codex 工具选择观察报告

## 目的

我用这组实验观察同一个 Agent 在三种信息条件下是否选择 `jq_query`，以及它能否正确调用、从 jq 错误中恢复，并在不适用的任务中避免调用工具。

本报告汇总每个“任务 × 条件”的一次描述性观察。它用于形成下一阶段的研究假设，不进行统计推断或因果归因。

## 运行信息

- 日期：2026-08-09
- Codex：codex-cli 0.147.0
- 仓库提交：a0738bf291e0cd4ac98c772069fa328da8645eab
- 模型配置：gpt-5.6-terra / medium
- 正式观察：8 个任务 × 3 种条件，共 24 次
- 执行方式：顺序执行，每个组合一次

模型配置由预设校准阶梯确定。`gpt-5.6-terra / medium` 是第一个完整通过 T1、T4、T7 校准门槛的配置。

## 条件

| 条件 | 定义 |
|---|---|
| `Explicit` | 提示词明确要求使用 `jq_query`；T8 明确要求不要使用 |
| `Description` | 只依赖 MCP 工具自身的名称、描述和输入 schema |
| `Skill` | 与 Description 使用相同任务提示，另外提供 jq 参考 Skill |

T1-T6 用于比较 Description 与 Skill 条件下是否主动选择 MCP。T7 明确要求先制造一次语法错误再修正，因此只评测恢复。T8 是纯文本任务，用于评测是否避免不必要的 jq 调用。

## 总体结果

| 指标 | 结果 | 分母含义 |
|---|---:|---|
| 任务成功 | 24/24 | 全部有效正式观察 |
| MCP 主动选择 | 5/12 | Description 与 Skill 条件下的 T1-T6 |
| 显式条件遵从 | 8/8 | Explicit 条件的全部任务 |
| 首次 MCP 输入有效 | 14/14 | 实际发生 MCP 调用的 T1-T7 |
| 错误恢复成功 | 3/3 | 三种条件下的 T7 |
| 负向任务避免调用 | 3/3 | 三种条件下的 T8 |

24 次运行均为有效轨迹，没有基础设施错误或待人工复核项。

## 条件对比

| 条件 | 成功 | MCP 主动选择 | 路径分布 |
|---|---:|---:|---|
| `Explicit` | 8/8 | 不适用 | MCP 6、混合 1、文件读取 1 |
| `Description` | 8/8 | 0/6 | Shell 4、文件读取 2、MCP 1、直接作答 1 |
| `Skill` | 8/8 | 5/6 | 混合 6、Shell 1、直接作答 1 |

这里的“混合”表示同一次运行既调用了 MCP，也执行了 Shell 命令。Description 条件中的 1 次 MCP 路径来自明确规定调用步骤的 T7，不计入 T1-T6 的主动选择分母。

### T1-T6 的选择差异

Description 条件在 T1-T6 中没有主动选择 MCP。模型仍然全部答对，但主要使用 Shell、直接读取文件或直接计算。Skill 条件在 T2-T6 中选择了 MCP，只有使用内联小数组的 T1 直接完成了计算。

这说明在当前观察中，仅仅暴露工具描述不足以让模型优先采用 MCP；参考 Skill 与更多 MCP 使用行为同时出现。不过单次观察不能排除采样波动、任务复杂度和上下文差异，因此这里不能写成 Skill 对工具选择存在已证明的因果效果。

### T7 的错误恢复

T7 要求第一次以精确过滤器 `if` 调用 `jq_query`。三种条件都观察到预期的 `JQ_SYNTAX_ERROR`，随后使用修正后的过滤器再次调用并返回活跃用户数量 `3`。三次恢复均成功，首次调用参数也都符合工具输入 schema；“输入结构有效”和“jq 程序语义有效”在这里是两个不同概念。

### T8 的负向避免

T8 只需统计 `notes.txt` 中的非空行，`jq_query` 不适用。三种条件均未调用 MCP，并都返回 `3`。它们分别通过普通文件读取或 Shell 完成任务，没有因为工具或 Skill 的存在而强行使用 jq。

公开的 `observations.json` 只保留任务编号、条件、有效性、布尔指标、路径分类、Token、耗时和脱敏备注。发布前已搜索绝对路径、会话标识、Bearer Token、API Key 模式和不当因果措辞。

## 局限与下一步

- 每个组合只有一次观察，无法估计方差、置信区间或结果稳定性。
- 八个任务规模较小，且主要围绕 JSON 与 jq，不能推广到其他工具类型。
- Codex 同时拥有 MCP、Shell 和文件读取能力，替代路径会影响工具选择。
- Skill 不只可能影响“是否调用”，还可能改变上下文长度和推理路径，本实验没有拆分这些因素。
- 校准和正式运行发生在同一天、同一 CLI 版本下，尚未检验版本变化带来的影响。

下一阶段我会考虑自定义 API Runner，对随机性、重复次数、工具可见性和上下文进行更严格的控制，并在重复采样后再讨论条件差异是否稳定。
